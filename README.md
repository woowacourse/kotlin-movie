# 3단계 - 영화 예매(데이터베이스)

## 구현할 기능 목록

### 1. 데이터베이스 환경 구성
- [x] H2 데이터베이스 의존성을 추가한다.
- [x] JDBC를 사용하여 데이터베이스에 연결할 수 있도록 설정한다.
- [x] 프로그램을 다시 실행하더라도 저장된 데이터를 조회할 수 있도록 파일 기반 데이터베이스로 구성한다.
- [x] 애플리케이션 실행 시 필요한 테이블을 생성하거나 초기화할 수 있다.

### 2. 상영 정보 영속화
- [x] 영화 정보는 데이터베이스에 저장한다. 
- [x] 영화 정보에는 영화 ID, 제목, 상영 시간이 포함된다. 
- [x] 상영 정보는 데이터베이스에 저장한다.
- [x] 상영 정보에는 상영 ID, 영화 ID, 상영관 ID, 시작 시각, 종료 시각이 포함된다.
- [x] 프로그램 실행 시 데이터베이스에 저장된 영화 및 상영 정보를 조회하여 `Movie`, `Screening`, `Screenings` 객체로 구성할 수 있다.

### 3. 예매 주문 정보 영속화
- [x] 예매 완료 시 하나의 결제 단위를 `reservation_orders`에 저장한다. 
- [x] 예매 주문 정보에는 사용 포인트, 결제 수단, 최종 결제 금액이 포함된다.
- [x] 하나의 예매 주문은 여러 개의 상영 예매 정보를 가질 수 있다.
- [x] 상영별 예매 정보는 `reservations`에 저장한다.
- [x] 상영별 예매 정보에는 예매 주문 ID와 상영 ID가 포함된다.
- [x] 각 상영 예매에 포함된 좌석 정보는 `reservation_seats`에 저장한다.
- [x] 좌석 정보에는 좌석 행, 좌석 열, 좌석 등급이 포함된다.
- [x] 프로그램 재실행 시 상영별 예약된 좌석 정보를 조회하여 `ReservedSeats`에 반영한다.

### 4. 좌석 예약 상태 반영
- [x] 특정 상영에 대해 이미 예약된 좌석 목록을 조회할 수 있다.
- [x] 조회한 예약 좌석 정보는 `ReservedSeats`에 반영된다. 
- [x] 이미 예매된 좌석은 다시 선택할 수 없다.

## 구현 전략
데이터베이스는 H2를 사용하고, 연동 방식은 JDBC를 사용한다.  
상영 정보와 예매 정보를 조회한 뒤 현재 도메인 객체로 복원할 수 있도록 구현하며,  
도메인 객체는 데이터베이스나 SQL을 직접 알지 않도록 유지한다.

테스트는 데이터베이스 저장/조회 자체를 검증하는 테스트와,  
조회한 데이터를 기반으로 기존 도메인 로직이 올바르게 동작하는지를 확인하는 테스트로 나누어 작성한다.

# 4단계 - 영화 예매(프레임워크)

## 구현할 기능 목록

### 1. Spring Boot 환경 구성
- [x] `spring-boot-starter-web` 의존성을 추가한다.
- [x] `jackson-module-kotlin` 의존성을 추가한다.
- [x] `@SpringBootApplication`을 사용하여 애플리케이션 진입점을 구성한다.
- [x] 기존 콘솔 기반 실행 방식을 Spring Boot 기반으로 전환한다.

### 2. 영화 목록 조회 API
- [x] `GET /api/movies` 요청 시 200 OK를 반환한다.
- [x] 응답에 모든 영화 정보(영화 ID, 제목, 상영 시간)가 포함된다.
- [x] 응답에 각 영화의 상영 정보(상영 ID, 시작 시각, 종료 시각)가 포함된다.
- [x] 응답 형식은 JSON이다.

### 3. 예매 생성 API
- [x] `POST /api/reservations` 요청 시 201 Created를 반환한다.
- [x] 요청 본문에 상영별 좌석 선택, 사용 포인트, 결제 수단을 포함한다.
- [x] 하나의 예매 주문에 여러 상영의 예매를 포함할 수 있다.
- [x] 응답에 예매 주문 ID, 예매 내역, 사용 포인트, 결제 수단, 최종 결제 금액이 포함된다.
- [x] 예매 완료 시 예매 정보를 데이터베이스에 저장한다.
- [x] 존재하지 않는 상영에 대해 예매를 요청하면 적절한 오류 응답을 반환한다.
- [x] 이미 예약된 좌석을 예매하려는 경우 적절한 오류 응답을 반환한다.
- [x] 잘못된 요청 형식에 대해 적절한 상태 코드를 반환한다.

### 4. 예외 처리
- [x] 존재하지 않는 상영에 대해 예매를 요청하면 적절한 오류 응답을 반환한다.
- [x] 이미 예약된 좌석을 예매하려는 경우 적절한 오류 응답을 반환한다.
- [x] 잘못된 요청 형식에 대해 적절한 상태 코드를 반환한다.
